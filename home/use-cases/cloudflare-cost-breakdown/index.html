The bill names the service, not the resource

See which Worker, bucket or Durable Object is behind your Cloudflare bill

CloudBridge reads your Cloudflare billable usage per day and splits each charge across your R2 buckets, Workers, D1 databases and Durable Object namespaces, in a ledger on your computer.

Download CloudBridge Read the Cloudflare docs

Free and open source for macOS and Windows. No account, no sync, no telemetry.

How it works

From an API token to cost per resource

One read-only token is enough. It stays in your system keyring.

  1. Create a token

    A custom API token with Account → Billing → Read. Add Account → Account Analytics → Read for the per-resource split.

  2. Add the account

    Enter the account ID and the token. CloudBridge reads the billable usage: spend per service, per day.

  3. Read the split

    Each day's charge is divided across the resources that used the meter. Insights lists each one's share and its usage this period.

What the numbers are

The parts add up to the bill

The split divides what Cloudflare billed; it doesn't invent a price. The rows are marked as estimates, because the analytics are sampled and a free allowance belongs to the account, not to one resource.

Insights Token permissions

  • A meter the analytics can't split, such as KV or Queues, keeps its row whole at the account.
  • Usage inside the free allowance is recorded too, at zero cost, because that is where a runaway starts.
  • Without the Account Analytics permission, the bill is still read; it just isn't split.
  • Pay-as-you-go accounts only. Cloudflare's billable usage API is in alpha and doesn't cover Enterprise.

Catch a runaway

Find out the first day a Worker starts looping

Nothing stops a pay-as-you-go Cloudflare account at a spending limit. Give the account a monthly budget and add an Account budget rule based on the month-end forecast: the first expensive day is projected across the month, and the alert fires on the first refresh that reads it.

Catch a runaway Cloud cost alerts

  • A real case: a dormant project's Durable Object alarm billed $10,811 before anyone knew. Read the post.
  • Shorten the refresh interval to 6 hours and keep CloudBridge in the menu bar with Open at login on.
  • When the alert fires, Insights shows each Worker's and namespace's share, so the one behind it stands out.

Privacy

Your bills stay on your machine

The ledger is a DuckDB file on your disk and the token is in the OS keyring. CloudBridge only reads from Cloudflare, and the bill sits beside your AWS, Azure, Google Cloud and model-provider bills in the same columns.

  • No CloudBridge account, no sync service, no telemetry.
  • Read-only token; nothing in your Cloudflare account is created or changed.
  • Open source under MIT.

FAQ

Questions people ask

Does Cloudflare's bill show the cost of each Worker or R2 bucket?

No. The bill stops at the service: it says how many R2 Class B operations or Durable Object rows were billed on a day, not which bucket or namespace used them. CloudBridge reads each resource's usage from Cloudflare's GraphQL Analytics API and splits each day's charge by those shares.

How accurate is the per-resource split?

The parts add up to what Cloudflare billed, and they are marked as estimates. Cloudflare's analytics are sampled, and a free allowance belongs to the account, not to any one resource.

Which permissions does the API token need?

Account, Billing, Read for the bill, and Account, Account Analytics, Read for the split. Both are read-only. The Insights resource scan needs a few more Read permissions and says which ones it was refused.

Does it work with a Cloudflare Enterprise account?

No. Cloudflare's billable usage API covers pay-as-you-go (self-serve) accounts only and is still an alpha API. CloudBridge reports an Enterprise account as not covered.

Can CloudBridge stop a runaway Worker or Durable Object?

No. It only reads. It can alert you on the first refresh that reads the expensive day, and Insights shows which Worker or namespace is behind the charge, so you can stop it in the Cloudflare dashboard.
