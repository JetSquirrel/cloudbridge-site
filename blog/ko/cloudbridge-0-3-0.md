# 0.3.0: 내 청구서를 직접 가져오기

<p class="post-meta">2026-09-11&emsp;릴리스&emsp;<a href="./">전체 글</a></p>

0.2.0은 CloudBridge에 하나의 팩트 테이블과 하나의 통화를 주었습니다. 한 가지를 빠뜨렸습니다. 청구 API가 언제나 청구서를 가장 잘 읽는 방법은 아니며, 때로는 읽는 방법이 아예 아닙니다. Alibaba Cloud의 `QueryBillOverview`는 Model Studio(百炼)를 한 달에 하나의 숫자로 보고합니다. DeepSeek의 API는 잔액만 알려 주고 그 돈이 어디에 쓰였는지는 말하지 않습니다. Volcengine, OpenAI, Anthropic에는 키가 없을 수도 있는 관리자 API가 있습니다.

그런데 그 콘솔에는 모두 다운로드 버튼이 있습니다. 0.3.0은 거기서 나온 파일을 원장으로 들어오는 정식 경로로 만듭니다.

## 두 번째 통로이지, 두 번째 스키마가 아닙니다

가져온 내보내기는 fetch가 만들어 내는 것과 똑같은 `fct_charge` 행이 됩니다. 그 아래 단계 — 대시보드, 알림, Sankey — 에서 가져온 달은 가져오지 않은 달과 구분되지 않습니다. 다른 점은 숨기지 않고 기록합니다. `ingest_batch.channel`이 해당 기간이 fetch로 들어왔는지 가져오기로 들어왔는지를 알려 주고, 가져온 달은 자동 fetch로 덮어쓰이지 않습니다. **강제 새로 고침에서도 마찬가지입니다.** 내보내기가 더 정밀한 판독이며, "강제"는 "최신성 창을 믿지 않는다"는 뜻이지 "가져온 것을 버린다"는 뜻이 아닙니다. 가져온 달을 갱신하려면 그 달의 수정된 내보내기를 다시 가져오면 됩니다.

가져오기는 파일이 포함하는 모든 달을 **교체**합니다. 그래야 합니다. 내보내기는 서비스가 직접 발행한 청구서이므로, 같은 달의 API 판독값에 더하면 그 달을 두 번 세게 됩니다.

현재 다섯 개 소스를 가져올 수 있습니다. Alibaba Cloud와 Volcengine 청구 상세(账单明细), OpenAI와 Anthropic의 비용 또는 사용량 내보내기, 그리고 DeepSeek입니다.

## 토큰 수는 돈이 아닙니다

사용량 내보내기에는 토큰 수만 있고 금액은 없습니다. 그런 행은 `billed_cost`가 NULL, `cost_basis = absent`로 저장됩니다. 정가로 가격을 매기면 아무도 청구받지 않은 숫자가 `billed_cost`에 들어가게 됩니다.

DeepSeek 콘솔은 같은 점을 더 날카롭게 보여 줍니다. 다운로드 파일은 CSV 두 개가 든 zip입니다. `cost-*.csv`의 금액 열 이름은 `cost`이고, `amount-*.csv`의 `amount` 열은 *토큰 수*입니다. 두 번째를 돈으로 읽으면 캐시 입력 토큰 10,787개를 쓴 하루가 ¥10,787로 기록됩니다. 그래서 CloudBridge는 zip을 열어 비용 쪽 절반만 읽고, 다른 절반은 이름을 들어 거부합니다. zip은 내려받은 그대로 가져오면 됩니다.

한편 열 이름은 중국어 콘솔, 영어 콘솔, 각 서비스의 API 필드 이름을 아우르는 별칭 목록으로 매칭됩니다. 이 내보내기 중 어느 것도 문서화된 파일 형식이 아닙니다. 아무것도 매칭되지 않는 열은 오류가 되고, 그 오류는 파일에 실제로 있는 열 이름을 알려 줍니다. UTF-8이 아닌 파일은 청구서의 제품 이름을 모두 망가뜨릴 추측으로 디코딩하는 대신, 고치는 방법을 안내하며 거부합니다.

## 크레딧이 가리는 것

크레딧을 뺀 순액은 헤드라인으로는 맞습니다. 실제로 지불한 금액이니까요. 추세의 기준으로는 틀립니다. 사용량이 크레딧으로 전부 덮이는 계정은 순액이 거의 0달러가 되고, 그 위에서 계산한 전월 대비 비율은 잡음입니다. 실제 한 계정은 −318.9%를 기록했습니다.

그래서 개요 화면은 이제 둘을 나눕니다. 헤드라인은 순액으로 두고, 총 사용량과 그것을 깎은 크레딧을 옆에 표시합니다. 추세를 내거나 순위를 매기는 모든 것 — 차트, 변화율, "어디에 쓰였나", 가장 크게 변한 항목 — 은 총 사용량을 기준으로 동작합니다. 무엇을 소비했는지와 얼마를 청구받았는지는 다른 질문이고, 이제 페이지는 둘을 평균 내는 대신 둘 다 답합니다.

헤더에는 기간 컨트롤도 생겼습니다. 이번 달 누적, 최근 30일 롤링, 최근 12개월입니다. 페이지의 모든 숫자는 선택한 기간에 맞춰 계산됩니다.

## 데스크톱 밀도

인터페이스는 [GPUI Kit](https://crates.io/crates/gpui-kit) 0.6으로 옮겼습니다. 세 개의 의존성이 하나가 되었고, tree-sitter 문법은 껐습니다. 비용 대시보드가 구문 강조 스택을 컴파일할 이유는 없습니다.

그와 함께 프레임워크가 열어 두는 결정 하나를 내렸습니다. 이것은 웹 페이지가 아니라 밀도 높은 데이터 도구입니다. 13px 기본 글꼴과 6px 카드 모서리는 테마 파일이 무엇을 제공하든 애플리케이션 수준에서 적용됩니다. 사이드바의 동기화 카드는 데스크톱 앱이 상태를 알리는 방식대로 창 아래쪽의 상태 표시줄이 되었습니다. 크기는 rem 스케일에서 파생되므로, 기본 글꼴을 키우면 인터페이스 전체가 함께 확대됩니다.

그리고 금액은 더 이상 1달러 미만 지출을 `$0`으로 반올림하지 않습니다. 100 이상은 정수, 1센트 이상은 소수 둘째 자리, 1센트 미만은 `<$0.01`로 표시됩니다. 작은 숫자는 이제 아무것도 아닌 값이 아니라 작은 숫자로 읽힙니다.

## 0.3.0의 다른 변경 사항

- **데모 데이터**, 설정에 있습니다. 계정 세 개와 현실적인 모양의 가짜 원장 12개월치를 버튼으로 불러오고 지웁니다. 데모 관련 항목은 모두 `demo-` 접두사로 구분되고 자격 증명이 없으며 새로 고침에서 건너뛰므로, 데모 행이 서비스 API에 도달하는 일은 없습니다.
- **계정당 키체인 항목 하나, 둘이 아니라.** macOS에서는 키체인을 읽을 때마다 암호 프롬프트가 뜰 수 있습니다. 항목의 접근 제어에 그것을 저장한 바이너리가 명시되므로, 다시 빌드하면 새 바이너리가 됩니다. 여러 기간을 가져오는 새로 고침은 기간마다, 키마다 그 비용을 치르고 있었습니다. 이제 두 값은 한 항목에 있고 세션마다 한 번 읽습니다. 아직 두 항목 형태로 남은 쌍은 첫 읽기에서 마이그레이션됩니다.
- **새로 고침 주기는 24시간이며 설정할 수 있습니다**(6, 12, 24, 48시간). 고정 6시간이었습니다. 서비스의 청구서는 하루보다 빨리, 그것도 비용을 치를 만큼 빨리 움직이지 않습니다.
- **알림 페이지의 "이번 달 해결됨"** 은 이제 알림이 해결된 때를 기준으로 하며, 발생한 때가 아닙니다.
- 설정 저장과 통화 전환은 UI 스레드 밖에서 실행되고, 저장 실패는 저장된 것과 혼동되지 않도록 별도 색으로 표시됩니다.

## 다음 계획

[로드맵](https://github.com/JetSquirrel/cloudbridge/blob/main/docs/roadmap.md)에는 P1의 나머지가 남아 있습니다. 브라우저가 아니라 정해진 일정에 도착하는 청구서를 위한 청구서 파일 *내보내기* 채널(S3 / OSS + Parquet), 그리고 명시적인 미할당 노드를 둔 태그 기반 배분입니다. Volcengine, OpenAI, Anthropic의 청구 API도 아직 남아 있습니다. 그 소스들은 필요한 자격 증명의 이름을 이미 붙인 채 레지스트리에 있습니다.
