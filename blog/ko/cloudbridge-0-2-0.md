# 0.2.0: 비용 뷰어가 원장이 되다

<p class="post-meta">2026-09-01&emsp;릴리스&emsp;<a href="./">전체 글</a></p>

0.1 버전은 서비스마다 숫자 하나를 보여 주고 그것을 합계라고 불렀습니다. 달러로 쓰는 AWS 계정과 위안으로 쓰는 Alibaba Cloud 계정이 있다면, 그 "합계"는 둘을 그냥 더했습니다. 크레딧은 사용량으로, 잔액은 지출로 읽혔습니다. 0.2.0은 그 숫자들이 딛고 서 있던 토대를 다시 만듭니다.

## 하나의 팩트 테이블

이제 모든 소스가 새 `billing.duckdb` 안의 단일 팩트 테이블 `fct_charge`로 정규화됩니다. 열 이름은 FinOps 재단의 공개 비용·사용량 명세인 [FOCUS](https://focus.finops.org/)를 따르므로, 크레딧은 `Credit`, 환불은 환불, 세금과 지원 비용은 각자의 이름으로 표시되고 금액은 부호를 그대로 유지합니다. Alibaba Cloud 바우처가 청구 금액의 일부를 덮으면 총액과 바우처가 각각 한 행씩 생기고, 그 행들을 더하면 실제로 지불한 금액이 됩니다. 설명할 수 없는 차이는 사라지지 않고 하나의 `Adjustment` 행이 됩니다.

스키마가 이미 FOCUS를 따르고 있기 때문에, 실제 청구서 내보내기 — AWS CUR이나 Alibaba Cloud 청구서 파일 — 은 나중에 스키마 변경 없이 그대로 들어올 수 있습니다.

## 원본 응답을 보관합니다

Cost Explorer는 요청당 0.01달러를 청구합니다. 그래서 같은 것을 두 번 묻는 일은 사용 패턴이 아니라 설계 결함입니다. 이제 모든 서비스 응답은 `raw/` 아래 Hive 파티션 Parquet로, 청구서 내보내기 버킷이 쓰는 것과 같은 레이아웃으로 그대로 디스크에 기록됩니다. 정규화는 저장된 배치에서 원장 행을 만들어 내는 순수 함수입니다. 결과는 두 가지입니다. 매핑을 고치면 새로 가져오는 비용을 치르는 대신 디스크에 있는 것을 다시 처리하고, 청구 로직을 기록된 응답으로 테스트할 수 있습니다.

## 하나의 통화

청구 항목은 청구된 통화로 저장되고 표시를 위해 환산되며, 각 환율은 해당 청구 항목보다 늦지 않은 날짜의 것입니다. 합계는 뷰 `v_charge_normalized`에서 나오므로, 설정에서 보고 통화를 바꾸면 뷰만 다시 만들고 아무것도 다시 쓰지 않습니다. 어떤 환율로도 환산되지 않는 통화의 청구 항목은 대시보드에 보고되며, 액면 그대로 조용히 합산되는 일은 없습니다.

## 자격 증명이 데이터베이스를 떠납니다

자격 증명은 이제 OS 키링(Windows 자격 증명 관리자, macOS 키체인)에만 있습니다. v1 마이그레이션이 데이터베이스에 남아 있던 자격 증명을 옮기고, 그것을 담고 있던 열을 삭제합니다. 이제 데이터베이스를 복사하거나 백업하거나 열어 봐도 키가 함께 따라가지 않습니다.

## 가져오기와 정규화를 분리합니다

청구 소스는 다섯 개의 `match` 분기를 가진 열거형이었습니다. 이제는 능력 기술자를 가진 테이블의 행이고, 두 메서드는 의도적으로 분리되어 있습니다. `fetch`는 네트워크를 건드리고 아무것도 해석하지 않으며, `normalize`는 해석하고 아무것도 건드리지 않습니다. 소스를 추가하는 일은 스위치보드를 고치는 대신 행과 매핑을 추가하는 일이 됩니다.

## 0.2.0의 다른 변경 사항

- macOS는 이제 Finder가 문서로 오인하던 압축된 단일 바이너리 대신, `CloudBridge.app`을 담은 `.dmg`로 배포됩니다.
- 새로 고침이 이제 두 번의 Cost Explorer 호출로 현재와 이전 청구 기간을 함께 읽습니다. 이전에는 대시보드가 세 번 호출했습니다.
- DeepSeek 잔액은 스냅샷으로 기록되며, 관측 사이에 충전된 잔액의 증가는 `Purchase`로 도출됩니다.
- 다크 모드 스위치가 실제로 테마를 바꿉니다.

## 다음 계획

[로드맵](https://github.com/JetSquirrel/cloudbridge/blob/main/docs/roadmap.md)은 P1을 제시합니다. 청구서 파일 내보내기 채널(S3 / OSS + Parquet), 명시적인 "미할당" 노드를 둔 태그 기반 배분, Sankey 비용 흐름입니다. 원장은 이 세 가지 모두의 전제 조건이었고, 이제 갖춰졌습니다.
