# 0.5.0: 계속 지켜봅니다

<p class="post-meta">2026-10-08&emsp;릴리스&emsp;<a href="./">전체 글</a></p>

비용 알림은 돈이 아직 나가고 있을 때만 의미가 있습니다. 지금까지 CloudBridge는 누군가 앱을 열고 새로 고침을 누를 때 청구서를 가져왔기 때문에, 창을 닫아 두는 동안 알림이 읽히지 않은 채로 남을 수 있었습니다. 이번 릴리스는 그 간극에 대한 것입니다. 창을 닫아도 앱이 계속 실행되고, 읽는 청구서가 돈을 쓴 리소스까지 내려가며, 잘못된 새로 고침이 더 이상 비용을 두 번 들이지 않습니다.

## 계속 실행됩니다

macOS와 Windows에서 창을 닫으면 CloudBridge는 메뉴 막대(Windows에서는 알림 영역)에 남습니다. 아이콘의 제목은 이번 달 지출이고, 처리되지 않은 알림이 있으면 그 옆에 개수가 붙습니다. 아이콘을 클릭하면 이번 달 누적, 월말 예상, 처리되지 않은 알림, 지난달 대비 가장 크게 움직인 서비스가 담긴 패널이 열립니다.

그 뒤에서는 15분마다 일정이 깨어나 새로 고칠 차례인 계정을 가져오고, 알림 규칙을 실행하고, 발동한 알림마다 시스템 알림을 보냅니다. 서비스에 다시 물어보기 전에는 여전히 새로 고침 주기를 기다리므로, 비용은 하루에 한 번 새로 고침하는 것과 같습니다. 설정 → 백그라운드에 있는 **로그인 시 열기**를 켜면 창을 열지 않고도 재시작 후 메뉴 막대에서 시작합니다.

Linux 빌드는 트레이 아이콘이 없어 여전히 창과 함께 종료됩니다. 일정과 알림은 앱이 열려 있는 동안 실행됩니다.

## Cloudflare, 리소스 단위까지

Cloudflare는 일곱 번째 소스입니다. 계정 ID와 Billing → Read 권한이 있는 API 토큰이면 과금 대상 사용량, 즉 서비스별·일별 지출을 읽습니다. 여기서는 일별이라는 점이 중요합니다. 반복에 빠진 Worker나 Durable Object는 월말 인보이스가 아니라 다음 날 원장에 들어옵니다.

다만 청구서는 서비스에서 멈춥니다. "10월 3일 R2 Class B 작업 734회"일 뿐, 어느 버킷인지는 알려 주지 않습니다. 토큰에 Account Analytics → Read를 더하면 CloudBridge가 Cloudflare의 GraphQL Analytics API에 각 리소스가 청구서에 적힌 계량 항목을 얼마나 썼는지 물어보고, 그 비중으로 하루치 행을 나눕니다. R2 버킷, Workers, D1 데이터베이스, Durable Object 네임스페이스가 각자의 몫을 갖고, 그 몫을 더하면 여전히 Cloudflare가 청구한 금액이 됩니다. 분석은 샘플링되고 무료 한도는 특정 리소스가 아니라 계정에 속하므로, 이 값들은 추정치로 표시됩니다.

무료 한도 안의 사용량도 비용 0으로 함께 보관합니다. 폭주는 대개 바로 그곳에서 시작됩니다. 첫 1센트가 청구되기 전에 며칠 동안 사용량이 올라갑니다.

## Insights: 무엇을 정리할까

Insights는 청구서를 실제로 돌아가는 것과 비교합니다. 선택 사항이며, **Set up and scan**이 먼저 물어본 뒤, 각 계정을 읽기 전용으로 스캔하는 [corkscrew](https://github.com/JetSquirrel/corkscrew/tree/cloudbridge-dist)(저희 포크)의 고정되고 체크섬이 검증된 빌드를 설치합니다.

AWS에서는 볼륨이 계속 과금되는 중지된 인스턴스, 유휴 공인 IPv4 주소, 소유자 태그도 없고 관리하는 스택도 없는 리소스, 청구서에는 있지만 스캔에서 빠진 리소스를 찾습니다. 각 항목은 계정이 Data Export를 읽는 경우 청구서를 기준으로 가격이 매겨집니다. Cloudflare에서는 Worker, R2 버킷, D1 데이터베이스, KV 네임스페이스, 존, Durable Object를 나열하고, 각각의 청구서 내 몫과 이번 기간 사용량을 함께 보여 줍니다.

큰 계정도 더 이상 페이지를 뒤덮지 않습니다. 모든 카드는 유형별 요약 — 개수와 비용 — 으로 열리고, 유형을 펼칠 때 리소스를 50개씩 나열합니다.

## 두 번 지불하는 일은 없습니다

이제 스스로 새로 고침하는 만큼, CloudBridge 자체가 여러분께 비용을 만들 수 있는 부분을 점검했습니다.

- **실패한 수집은 새로 고침 주기 안에서 다시 가져오지 않습니다.** AWS가 요청에 응답했는데 그 응답을 저장하다 실패하면(디스크가 가득 찼거나 매핑 버그), 이전에는 일정이 15분마다 같은 데이터를 다시 사들였습니다. 이제는 주기를 기다리며 이유를 알려 주고, 강제 새로 고침은 여전히 곧바로 다시 시도합니다.
- **실패하는 계정은 점점 덜 재시도합니다.** 대기 시간은 15분에서 시작해 새로 고침 주기까지 두 배씩 늘어나고, 해당 계정의 새로 고침이 멈췄다는 알림이 옵니다.
- **변경되지 않은 AWS Data Export의 달은 다시 내려받지 않습니다.** 파일의 ETag를 먼저 확인합니다.
- **Cost Explorer의 달은 전부 읽습니다.** 큰 달은 여러 페이지로 나뉘어 오는데, 이전에는 첫 페이지만 읽었습니다. 추가 페이지는 각각 과금되는 요청이며, 최대 20페이지까지입니다.

## 작은 것들

- **서비스 분류가 모든 클라우드에서 같은 뜻을 가집니다.** ECS, EC2, Volcengine의 ECS는 모두 Compute / Virtual Machines이므로, 비용 귀속 페이지의 분류 보기에서 클라우드를 비교할 수 있습니다. 기존 원장은 처음 열 때 마이그레이션됩니다.
- **무엇을 읽는지 보여 주는 홈페이지.** 문서 사이트가 지원하는 모든 클라우드와 모델 플랫폼을 로고와 함께 나열합니다.

## 다음 계획

Cloudflare 자체의 발견 사항, 그중에서도 알람이 계속 설정된 객체를 가진 Durable Object 네임스페이스부터는 제대로 판단하려면 실제 스캔이 필요합니다. Volcengine, OpenAI, Anthropic의 청구 API도 아직 남아 있습니다. 그때까지는 그 서비스들의 내보내기를 가져와 씁니다.
