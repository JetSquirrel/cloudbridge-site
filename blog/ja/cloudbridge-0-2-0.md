# 0.2.0: コストビューアから台帳へ

<p class="post-meta">2026-09-01&emsp;リリース&emsp;<a href="./">すべての記事</a></p>

バージョン 0.1 は、プロバイダーごとに数字を 1 つ見せて、それを合計と呼んでいました。ドルの AWS アカウントと人民元の Alibaba Cloud アカウントがあれば、「合計」はその 2 つを足していました。クレジットは使用量として読まれ、残高は支出として読まれていました。0.2.0 は、そうした数字が立っている地面を作り直します。

## 1 つのファクトテーブル

すべてのソースは、新しい `billing.duckdb` にある単一のファクトテーブル `fct_charge` に正規化されるようになりました。列名は FinOps Foundation のオープンなコスト・使用量仕様である [FOCUS](https://focus.finops.org/) にちなんで付けられているので、クレジットは `Credit`、返金は返金、税金とサポート費用はそれぞれの名前でラベル付けされ、金額は符号を保ちます。Alibaba Cloud のバウチャーが明細の一部をカバーする場合、総額とバウチャーはそれぞれ別の行になり、その行の合計は実際に支払った額になります。説明できない差額は消えるのではなく、1 つの `Adjustment` 行になります。

スキーマがすでに FOCUS を話すので、実際の請求書エクスポート（AWS CUR や Alibaba Cloud の請求ファイル）を、スキーマを変えずに後から投入できます。

## 生の回答を残す

Cost Explorer はリクエストごとに $0.01 を請求するので、同じものを二度尋ねるのは利用パターンではなく設計上の欠陥です。プロバイダーの応答はすべて、`raw/` 以下の Hive パーティションの Parquet として、そのままディスクに書き込まれるようになりました。請求書エクスポートのバケットが使うのと同じレイアウトです。正規化は、保存されたバッチから台帳の行への純粋な関数です。結果として 2 つのことが起きます。マッピングの修正は、別の取得に料金を払う代わりにディスク上のデータを再生します。そして課金ロジックは、記録された応答からテストできます。

## 1 つの通貨

明細は請求された通貨で保存され、表示用に換算されます。換算レートは明細自体より後の日付のものは使いません。合計は `v_charge_normalized` ビューから得られるので、設定で報告通貨を切り替えるとビューが再構築されるだけで、何も書き換わりません。レートのない通貨の明細はダッシュボードで報告されます。パーで黙って計上されることはありません。

## 認証情報がデータベースから出ていく

認証情報は OS のキーチェーン（Windows 資格情報マネージャー、macOS キーチェーン）にのみ置かれるようになりました。v1 のマイグレーションは、まだデータベースに残っていたものを移動し、それらを保持していた列を削除します。データベースは、キーを持ち歩くことなくコピー、バックアップ、調査できます。

## 取得と正規化を分ける

請求ソースは以前、5 つの `match` アームを持つ enum でした。今は能力記述子を持つテーブルの行で、2 つのメソッドは意図的に分かれています。`fetch` はネットワークに触れ、何も解釈しません。`normalize` は解釈し、何にも触れません。ソースの追加は、スイッチボードを編集することではなく、行とマッピングを追加することになりました。

## 0.2.0 のそのほか

- macOS は、Finder がドキュメントと見なしていた裸のバイナリの zip ではなく、`CloudBridge.app` を収めた `.dmg` として提供されます。
- 更新は、現在と前の請求期間を 2 回の Cost Explorer 呼び出しで取り込むようになりました（以前のダッシュボードは 3 回でした）。
- DeepSeek の残高はスナップショットとして記録されます。観測間のチャージ後残高の増加は `Purchase` として導出されます。
- ダークモードのスイッチが実際にテーマを切り替えます。

## 次にくるもの

[ロードマップ](https://github.com/JetSquirrel/cloudbridge/blob/main/docs/roadmap.md) は P1 を示しています。請求ファイルのエクスポート経路（S3 / OSS + Parquet）、明示的な「未割り当て」ノードを持つタグベースの配賦、Sankey のコストフローです。台帳はその 3 つすべての前提でした。それが今、整いました。
