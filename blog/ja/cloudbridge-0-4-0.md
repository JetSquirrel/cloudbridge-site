# 0.4.0: 入口が増え、読み方も増える

<p class="post-meta">2026-10-05&emsp;リリース&emsp;<a href="./">すべての記事</a></p>

0.3.0 はすべての請求書を 1 つの台帳に入れ、0.3.1 はインターフェースをそれ自身と一致させました。0.4.0 はその台帳の両端で作業します。入口では、AWS アカウントが Cost Explorer に尋ねるのではなく、AWS が S3 に書き出すエクスポートから請求書を読めるようになりました。出口では、すでにあるものを読む方法が 4 つ増えました。モデルごと、ディメンションごと、予算に対して、そして SQL で。さらに同じアプリケーションがブラウザで動くので、何もインストールする前にすべてを試せます。

## S3 から読む AWS Data Exports

Cost Explorer は合計で答え、問いごとにリクエストの料金がかかります。AWS の Data Exports（CUR 2.0、「FOCUS 1.2 with AWS columns」の形）は、請求書全体、つまりリソース ID、タグ、各行がどのリンクアカウントで請求されたかを、自分が所有する S3 バケットに書き出します。AWS アカウントにエクスポートの `s3://bucket/prefix` URI を渡すと、更新は代わりにそこから読みます。Parquet でも gzip 圧縮の CSV でも、エクスポートが届けるよう設定されていた形式で読みます。

間違えやすいところをいくつか正しく扱っています。

- **月は 1 回だけ数えられる。**「新規作成」に設定されたエクスポートは、すべての納品を並べて保持します。CloudBridge はその期間のマニフェストが名指しするファイルだけを読むので、9 月を 12 回更新しても 9 月は 1 つです。
- **納品されていないものはゼロではない。** エクスポートがまだ書き出していない期間はスキップされ、空の月として保存されることはありません。
- **支払者アカウントのエクスポートはメンバーアカウントごとに分かれる。** 各行は `SubAccountId` と `SubAccountName` を保持します。

S3 の保存とリクエストの料金はかかり、Cost Explorer のポリシーは S3 へのアクセスを許可しません。[権限のページ](https://cloudbridge.jetsquirrel.cloud/docs/permissions#aws-s3) に、エクスポート経路に必要な最小限のポリシーがあります。URI のないアカウントは Cost Explorer を使い続けます。

## モデルページ

台帳は 0.2.0 から LLM のコストの隣にトークン量を保存していましたが、それを読むものはありませんでした。新しいモデルページがそれを読みます。選んだ範囲について、各モデルはコストと変化、入力・出力・キャッシュのトークン数、100 万トークンあたりの混合コストとキャッシュ比率を得て、その下に日次トークンのグラフが付きます。

また、目立つことも教えてくれます。キャッシュ読み取りが入力側の 5% 未満のモデルは、キャッシュ料金で済むはずのものに入力料金を払っています。モデル支出の 70% 以上を 1 つのモデルが担っているなら知っておく価値があります。トークン計測なしで請求されているモデルはそのように指摘されます。単価が計算できないからです。そして支出の増加は 2 つの期間のトークン数と照合されます。増えたトークンが増加を説明するならそれは使用量であり、説明しないときに限り単価の上昇として報告されます。

Alibaba Cloud と Volcengine の請求項目テキストに埋もれたモデル名はまだ抽出していません。OpenAI、Anthropic、DeepSeek の取り込みはモデル名を直接持っています。

## 台帳を読むほかの方法

- **クエリ。** ローカルの DuckDB 台帳に対する読み取り専用の SQL コンソールで、スターターテンプレート付き。実行できるのは読み取りの文だけで、いずれにせよ台帳はそれらのために読み取り専用で開かれます。デスクトップのみです。
- **予算。** ルールページはアカウントごとの月次予算を保持し、「アカウント予算」ルールは、今日までのコストまたは月末予測に対して、パーセンテージまたは金額で警告します。異常検知ルールも 1 つのアカウントに絞り込めるようになりました。
- **ディメンションごとの内訳。** 帰属はタグ、サービス、リージョン、サービスカテゴリを切り替え、ツリーマップ（面積がコスト、色が変化）またはシェアバーで描かれ、その横にその期間で最も高価なリソースが並びます。アカウントの詳細ページにも同じドリルダウンがあります。
- **データの健全性。** 合計を実際より信頼できなくするものの検出結果です。レート表が換算できない通貨、帰属タグやリージョンのない使用量、どの明細でも説明できない調整。1 つを却下すると、その期間については却下されたままになります。

## ブラウザの CloudBridge

このクレートは WebAssembly 向けにもビルドされるようになりました。[デモ](https://cloudbridge.jetsquirrel.cloud/demo/) はモックアップではありません。ページ、ビューモデル、アラートルールはデスクトップ自身のコードで、DuckDB、プロバイダーの API、キーチェーンの代わりにデモの請求書を入れたインメモリの台帳の上で動いています。クエリ、ルール、設定はデスクトップに残りますが、それ以外のすべて、モデルページも含めてそこにあります。

それを保つため、CI はブラウザ版を必須のチェックとしてビルドし、両方のビルドが計算する統計（予測、比較、分解、検出結果）は、バックエンドごとのコピーではなく、1 つの共有されたテスト済みモジュールにあります。

## 小さなこと

- **アカウントの削除は履歴について尋ねます。** 以前は明細が黙って残り、説明するアカウントがないまま合計に数えられ続けていました。削除ダイアログはそれらも削除するかを提案し、以前の削除で残った履歴はアカウントページに表示され、そこから削除できます。
- **どこかに向かう初回起動。** 空の概要はアカウントの追加かデモの請求書の読み込みを提案し、API アカウントを保存するとすぐにその請求書を取得します。
- **キーボードショートカット。** ⌘1〜⌘9 でページを切り替え、⌘R で再読み込みします。
- **ウィンドウが先に開く。** ストアは開き、ページはバックグラウンドで、各ページは初回の訪問時に読み込まれます。
- **支出グラフの塗り**が、グラフを横切る斜めのくさびを切らなくなりました。
- **セキュリティ：** rustls と quick-xml は 3 件の RUSTSEC 勧告を越えてアップグレードされました。
- **Rust 1.95** が宣言された最小バージョンです。古い宣言はビルドできるものではありませんでした。

## 次にくるもの
