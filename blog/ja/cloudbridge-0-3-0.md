# 0.3.0: 自分の請求書を持ち込む

<p class="post-meta">2026-09-11&emsp;リリース&emsp;<a href="./">すべての記事</a></p>

0.2.0 は CloudBridge に 1 つのファクトテーブルと 1 つの通貨を与えました。1 つだけ残していました。課金 API は常に請求書の最良の読み方とは限らず、時には読み方にすらならないことです。Alibaba Cloud の `QueryBillOverview` は Model Studio（百炼）を月に 1 つの数字として報告します。DeepSeek の API は残高を報告し、そのお金が何に使われたかは何も報告しません。Volcengine、OpenAI、Anthropic には、キーを持っていないかもしれない管理 API があります。

しかし、それらのコンソールにはどれもダウンロードボタンがあります。0.3.0 は、そこから出てくるものを台帳への第一級の入口にします。

## 2 つ目の経路であって、2 つ目のスキーマではない

取り込まれたエクスポートは、取得が生み出すのと同じ `fct_charge` の行になります。下流、つまりダッシュボード、アラート、Sankey にとって、取り込まれた月と取得された月は区別できません。違うのは隠されるのではなく記録されます。`ingest_batch.channel` は、その期間が取得で来たのか取り込みで来たのかを示し、取り込まれた月が自動の取得で上書きされることは決してありません。**強制更新のときも含めて**です。エクスポートのほうが細かい読み方であり、「強制」は「鮮度の窓を信じない」という意味で、「取り込んだものを捨てる」という意味ではありません。取り込んだ月を更新するには、その月の修正済みエクスポートを取り込みます。

取り込みは、ファイルが対象とするすべての月を**置き換え**ます。そうする必要があります。エクスポートはプロバイダー自身の請求書なので、同じ月の API の読みに足すと、その月を二重に数えることになるからです。

現在取り込めるのは 5 つのソースです。Alibaba Cloud と Volcengine の請求明細（账单明细）、OpenAI と Anthropic のコストまたは使用量のエクスポート、そして DeepSeek です。

## トークン数はお金ではない

使用量のエクスポートはトークン数を持ち、金額を持ちません。そうした行は `billed_cost` が NULL、`cost_basis = absent` として保存されます。定価で価格を付けると、誰も請求されていない数字を `billed_cost` に入れることになります。

DeepSeek のコンソールは同じ点をより鋭く示します。ダウンロードは 2 つの CSV の zip です。`cost-*.csv` の金額列は `cost` という名前で、`amount-*.csv` の `amount` という名前の列は*トークン数*です。2 つ目を金額として読むと、キャッシュ入力トークン 10,787 の 1 日が ¥10,787 として計上されます。そこで CloudBridge は zip を開き、コストの半分を読み、もう半分は名前で拒否します。zip はダウンロードしたそのままを取り込みます。

列名は、中国語コンソール、英語コンソール、各プロバイダーの API フィールド名をカバーするエイリアスリストで照合されます。これらのエクスポートはいずれも文書化されたファイル形式ではありません。何にも一致しない列は、ファイルに実際にある列名を示すエラーになります。UTF-8 でないファイルは、請求書のすべての製品名を壊してしまうような推測でデコードされるのではなく、修正方法を示して拒否されます。

## クレジットが隠すもの

クレジットを差し引いた合計は、見出しとしては正しいものです。実際に支払った額だからです。しかしトレンドの基準としては誤りです。使用量がクレジットで完全にカバーされているアカウントは純額でほぼ $0 になり、それで計算した前月比はノイズです。ある実在のアカウントは −318.9% を出しました。

そこで概要は 2 つを分けるようになりました。見出しは純額のままで、総使用量とそれを下げたクレジットがその横に表示されます。トレンドやランキングを行うもの、つまりグラフ、変化率、「どこに使われたか」、変動の大きい項目は、総使用量で動きます。何を消費したかと何を請求されたかは別の問いであり、ページは両者を平均するのではなく、両方に答えるようになりました。

ヘッダーには範囲のコントロールも付きました。月初来、直近 30 日間のローリング、直近 12 暦月です。ページのすべての数字は、選んだ窓について計算されます。

## デスクトップの密度

インターフェースは [GPUI Kit](https://crates.io/crates/gpui-kit) 0.6 に移ります。3 つの依存が 1 つになり、tree-sitter の文法は無効化されます。コストダッシュボードが構文ハイライトのスタックをコンパイルする理由はないからです。

それに伴い、フレームワークが開いたままにしていた判断をしました。これは Web ページではなく高密度のデータツールです。13px の基本フォントと 6px のカード半径を、テーマファイルが何を提供するかにかかわらずアプリケーションレベルで適用します。サイドバーの同期カードは、デスクトップアプリが状態を伝える形で、ウィンドウ下部のステータスバーになりました。サイズは rem スケールから導かれるので、インターフェース全体は基本フォントに合わせて拡大縮小します。

そして金額は、1 ドル未満の支出を `$0` に丸めるのをやめました。100 以上は整数、1 セント以上は小数 2 桁、1 セント未満は `<$0.01` です。小さい数字が、何もないのではなく小さい数字として読めるようになりました。

## 0.3.0 のそのほか

- **設定のデモデータ**：3 つのアカウントと 12 か月分の、現実的な形の偽の台帳。ボタンで読み込みと消去ができます。デモのものはすべて `demo-` プレフィックスのキーで、認証情報を持たず、更新ではスキップされるので、デモの行がプロバイダーの API に届くことはありません。
- **キーチェーン項目はアカウントごとに 1 つ、2 つではない。** macOS ではキーチェーンの読み取りごとにパスワードのプロンプトが出ることがあります。項目のアクセス制御は、それを保存したバイナリを名指しするので、再ビルドは新しいバイナリです。複数の期間を取得する更新は、期間ごと・キーごとにそのコストを払っていました。ペアは 1 つの項目になり、セッションごとに 1 回読み取られます。古い 2 項目形式のペアは初回の読み取りで移行します。
- **更新間隔は 24 時間で、設定可能**（6、12、24、48）。以前は固定の 6 でした。プロバイダーの請求書は、料金を払う価値のある形で 1 日より速く動くことはありません。
- **アラートページの「今月解決したもの」**は、警告が上がった時ではなく解決した時を基準にします。
- 設定の書き込みと通貨の切り替えは UI スレッドの外で実行され、保存に失敗した場合は専用の色で表示されるので、保存済みと誤解されません。

## 次にくるもの

[ロードマップ](https://github.com/JetSquirrel/cloudbridge/blob/main/docs/roadmap.md) には P1 の残りがあります。ブラウザ経由ではなくスケジュールで届く請求書のための請求ファイル*エクスポート*経路（S3 / OSS + Parquet）と、明示的な未割り当てノードを持つタグベースの配賦です。Volcengine、OpenAI、Anthropic の課金 API はまだ残っています。それらのソースはレジストリにあり、それぞれが必要とする認証情報の名前はすでに付けられています。
