# 0.5.0: 見張り続ける

<p class="post-meta">2026-10-08&emsp;リリース&emsp;<a href="./">すべての記事</a></p>

コストアラートは、お金がまだ使われている間だけ価値があります。これまで CloudBridge は、誰かが開いて更新を押したときに請求書を取得していたので、ウィンドウが閉じたままならアラートは読まれずに放置され得ました。このリリースはその隙間についてです。アプリはウィンドウを閉じても動き続け、読む請求書はそれを費やしたリソースまで下り、失敗した更新は同じものに二度料金を払いません。

## 動き続ける

macOS と Windows では、ウィンドウを閉じても CloudBridge はメニューバー（Windows では通知領域）に残ります。アイコンのタイトルは今月の支出で、未対応のアラートがあればその数が横に付きます。クリックすると、月初来、月末予測、未対応のアラート、前月比で最も動いたサービスを並べたパネルが開きます。

その背後で、スケジュールが 15 分ごとに起き、期限が来たアカウントを取得し、アラートルールを実行し、発火したアラートごとにシステム通知を出します。プロバイダーに再び尋ねる前に更新間隔を待つので、コストは 1 日 1 回の更新と同じです。設定 → バックグラウンドの **ログイン時に開く** は、再起動後にウィンドウを開かずにメニューバーで起動します。

Linux のビルドにはトレイアイコンがなく、今もウィンドウと一緒に終了します。スケジュールと通知は開いている間だけ動きます。

## Cloudflare、リソースまで

Cloudflare は 7 つ目のソースです。アカウント ID と Billing → Read を持つ API トークンで、課金対象の使用量、つまりサービスごと・日ごとの支出を読みます。ここでは日次が重要です。ループし始めた Worker や Durable Object は、月末の請求書ではなく翌日の台帳に入ります。

ただし請求はサービスで止まります。「R2 Class B operations, 734 on 3 October」であって、どのバケットかは分かりません。トークンに Account Analytics → Read を加えると、CloudBridge は Cloudflare の GraphQL Analytics API に、請求が名指しするメーターのリソースごとの使用量を尋ね、そのシェアで各日の行を分割します。R2 バケット、Workers、D1 データベース、Durable Object ネームスペースがそれぞれの分を得て、その合計は Cloudflare が請求した額のままです。これらは推定として示されます。分析はサンプリングされ、無料枠はアカウントに属し、どのリソースにも属さないからです。

無料枠内の使用量も、コスト 0 とともに保持されます。そこがたいてい暴走の始まりだからです。使用量は最初の 1 セントが請求される前に何日も上がり続けます。

## インサイト：何を削るか

インサイトは請求書と、実際に動いているものを比較します。任意の機能です。**セットアップしてスキャン** は最初に確認し、それから固定されチェックサムで検証された [corkscrew](https://github.com/JetSquirrel/corkscrew/tree/cloudbridge-dist)（私たちのフォーク）のビルドをインストールし、それが各アカウントを読み取り専用でスキャンします。

AWS では、ボリュームがまだ課金されている停止中のインスタンス、遊休のパブリック IPv4 アドレス、所有者タグも管理するスタックもないリソース、請求されているのにスキャンにないリソースを見つけます。それぞれは、アカウントが Data Export を読んでいれば請求書から価格が付きます。Cloudflare では Workers、R2 バケット、D1 データベース、KV ネームスペース、ゾーン、Durable Objects を一覧し、それぞれに請求に占める分と今期間の使用量を付けます。

大きなアカウントがページを溢れさせることはなくなりました。各カードは種類ごとの要約（件数とコスト）で開き、種類を開いたときにだけ、50 件ずつリソースを並べます。

## 二度払いはしない

CloudBridge 自身がいくらかかるかを、自分で更新するようになった今、監査しました。

- **失敗した取り込みは更新間隔の内に再取得されません。** AWS がリクエストに答え、その回答の保存が失敗した場合（ディスク満杯、マッピングのバグ）、以前のスケジュールは 15 分ごとに同じデータを買い直していました。今は間隔を待ち、理由を伝えます。強制更新は今もすぐに再試行します。
- **失敗するアカウントは徐々に再試行が減ります。** 待ち時間は 15 分から始まり、更新間隔まで倍々になり、そのアカウントの更新が止まったことを通知が伝えます。
- **変更のない AWS Data Export の月は再ダウンロードされません。** まずファイルの ETag を確認します。
- **Cost Explorer の月は全体が読まれます。** 大きな月はページに分かれて返り、以前は最初のページだけが読まれていました。追加のページはそれぞれ課金されるリクエストで、上限は 20 ページです。

## 小さなこと

- **サービスカテゴリはどのクラウドでも同じ意味になります。** ECS、EC2、Volcengine の ECS はすべて Compute / Virtual Machines なので、帰属ページのカテゴリビューでクラウドを比較できます。既存の台帳は初回の起動時に移行されます。
- **読むものを示すホームページ。** ドキュメントサイトは、対応するすべてのクラウドとモデルプラットフォームをロゴ付きで一覧します。

完全なリストは [変更履歴](https://github.com/JetSquirrel/cloudbridge/blob/main/CHANGELOG.md) にあります。

## 次にくるもの

Cloudflare 自身の検出結果、まずアラームを立て続けるオブジェクトを持つ Durable Object ネームスペースは、判断するために実際のスキャンを必要とします。Volcengine、OpenAI、Anthropic の課金 API はまだ残っています。それまでは、それらのエクスポートが取り込めます。
